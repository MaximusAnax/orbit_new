# TickerPress — Scoping Review & Resolutions

Audit trail for the scoping critique loop. Two adversarial reviews were run
against the first draft of `SCOPE.md`, `DATA_MODEL.md`, and `EVALS.md`:

- **DESIGN** — verdict: no blockers, 2 majors, 7 minors. "Fix the two majors
  and pin the minors, and this is ready to build."
- **EVALS** — verdict: 1 blocker, 5 majors, 3 minors. "The suite as designed
  could still certify a bad product on hard part A."

All 18 findings were addressed in the docs; none were rejected. Two
*sub-recommendations* were declined in favour of a different fix for the same
finding, and both are recorded below (D1, D2).

## Findings

| # | Source | Severity | Finding | Resolution |
|---|---|---|---|---|
| D1 | design | major | FR-6 mandated a per-alias θ override with no home: no `Alias.threshold` field, no column, no CLI option, no API schema. `Mention.threshold` implied per-row variation with no way to set it. | **Fixed by removal.** FR-6 now states θ is a single committed engine constant with no per-alias/per-company override; `Mention.threshold` is explicitly provenance-only (interpretable across `engine_version`s). DATA_MODEL §2.2 records "deliberately no threshold column"; a new non-goal 10 states the boundary; the API alias POST body is now spelled out and has no threshold field. *The reviewer's alternate branch (add column + `--threshold` + API field) was declined:* it adds storage, CLI, API and eval surface for a knob a single user does not need, and `prior` + `context_terms`/`anti_terms` already give per-surface tuning. |
| D2 | design | major | D18's scope valves authorised cutting the webhook notifier, alert mode, and Atom support — all three verbatim locked decisions. An implementer under line pressure would ship a lock violation believing the docs allowed it. | **Fixed.** D18's valve list was rewritten to cut only non-locked surface, in order: (1) drop report-only eval outputs except `naive_deltas`; (2) trim the API to the read/ingest/digest core (CLI keeps full coverage; the locks name no API surface); (3) drop `--json` on `explain`; (4) shrink the fixture corpus toward its asserted floors, never dropping a trap class. An explicit sentence now states that alerts, Atom, and the live notifiers are locked and **not** valves, and that further pressure requires re-negotiating a locked decision with the owner as a new numbered decision. *The reviewer's "shrink 62→45 bases" valve was declined in that form* — the corpus grew instead (see E9) and shrinkage is bounded by the §4 floors; the "InMemoryRepository = sqlite `:memory:`" suggestion was adopted as a permanent decision rather than a valve (see D8). |
| D3 | design | minor | FR-6's worked examples contradicted its own `case_signal` definition (title-initial "Apple" was granted +.10 case), and the docs never said whether a title counts as a sentence or whether the ±12-token window crosses field boundaries — yet EVALS §7 bakes the examples into `test_disambig`. | **Fixed.** FR-6 gained five numbered scoring rules: the title is one sentence (so its first token *is* sentence-initial); windows are clipped to the mention's own field; window and doc counts are disjoint by position; global lexicons and per-company terms score independently; `coref_strong` is resolved after all strong candidates. The worked examples were recomputed into an exact four-row feature-vector table (Mumbai .25+.15 = **.40** accept; growers −.65 → **0** reject; Meta-analysis −.50 → **0** reject; plus a coreference accept that clamps to 1.0). DATA_MODEL mention 902 is annotated as the `case_signal = 0` title-initial case. |
| D4 | design | minor | `Article.token_count` was annotated "lede rule input" but stores the cross-field total, while FR-8's lede rule needs the first 25% of **content** tokens — the stored field cannot compute the rule. | **Fixed.** Added `content_token_count` (content field only, 0 when `content` IS NULL) as the FR-8 lede-rule input, with a SQL column, a CHECK tying it to content nullity, and an entry in the article example. `token_count` is now labelled reporting metadata only. FR-8 states the lede window is `ceil(0.25 · content_token_count)` and that a NULL content leaves only the summary-sentence path. |
| D5 | design | minor | FR-7 left the argmax-J tie-break, the ingest comparison order, and the window-scope of the canonical-url/content-hash fast paths unspecified — yet M5 demands byte-identical story assignment, so these are determinism-critical. | **Fixed.** FR-7 gained an explicit determinism block: candidates compared in ascending article id, J ties resolve to the smallest article id, `canonical_url` beats `content_sha256` when both fast paths fire on different articles, fast-path lookups are window-limited to the same ±7 days, and fast-path joins record `dedup_similarity = 1.0`. FR-2 pins feed iteration to ascending feed id and FR-3 pins item processing to document order, making article ids a pure function of the fixture bytes. |
| D6 | design | minor | Engine purity risk: lexicons live in `data/` but no doc said who reads them; CONVENTIONS.md forbids filesystem access in `engine/`. `init … load lexicons` was undefined. | **Fixed.** SCOPE architecture adds `resources.py` (the only module that reads `data/`, via `importlib.resources`, producing an immutable `Lexicons` dataclass with its fields enumerated) and `services.py` (composition layer that passes `Lexicons` into engine functions). An explicit paragraph states no `engine/` module opens a file, reads a clock, or touches the network, and that tests can inject synthetic `Lexicons`. CLI `init` is redefined as "create schema; validate every lexicon loads; print entry counts + sha256; idempotent". DATA_MODEL §1 mirrors this. |
| D7 | design | minor | `alias_id` semantics for pattern hits were ambiguous — an exchange-qualified `(NASDAQ: AAPL)` is matched by regex, not an alias row, and the settling example was "omitted for brevity". | **Fixed.** DATA_MODEL §2.7 adds an alias-attribution table: `alias` → the matching alias row; `cashtag` → the `$TICKER` cashtag alias; `exchange_qualified` → the `ticker_symbol` alias. A NULL `alias_id` therefore always means "alias since removed", never "recognizer has no alias". The previously omitted mention row (id 903, article 117's exchange-qualified `AAPL`, `alias_id: 1`) is now written out, so `mention_count: 3` reconciles. |
| D8 | design | minor | The exactly-once contract is enforced by a SQLite partial unique index, but CONVENTIONS.md also promises an `InMemoryRepository`; a dict backend would silently lack the constraint, making ledger tests backend-dependent. | **Fixed.** DATA_MODEL §4 states `InMemoryRepository(...)` is a thin factory returning `SQLiteRepository(":memory:")` — one implementation, not two — so constraint semantics are identical everywhere. Echoed in SCOPE's architecture tree and D8, in DATA_MODEL §2.10's invariants, and in the FR-11 test row ("in-memory backend has the same constraint"). |
| D9 | design | minor | Three small defects: (a) §3.2 webhook example showed relevance 93 where §2.8/§3.1/§5 show 94; (b) pairwise link P/R was credited to Bagga & Baldwin 1998, which introduces B-CUBED; (c) `dry_run` never said whether it writes a `composed` Delivery row. | **Fixed.** (a) Corrected to 94, with a note that it is the same value carried by the `delivery_items` row. (b) EVALS M2 now cites the pair-counting (pairwise link) convention and explicitly notes it is *not* B-CUBED. (c) FR-9 states a dry run renders and returns the body and persists **nothing** — no Delivery, no DeliveryItem, no notifier call — so it never consumes a story; mirrored in DATA_MODEL §2.9, the API sketch, and a new M4 check 6 that asserts zero rows after a dry run. |
| E1 | evals | **blocker** | The H1 gates are defeatable by per-article memorization in the uncapped global lexicons (add "Mumbai"/"flagship" as cues and "frost"/"statin" as anti-cues — disjoint per article, so precision and recall rise together). EVALS' central anti-gaming claim ("stuffing the cue list cannot raise precision and recall simultaneously") is false, and SCOPE D4's tune-on-the-fixtures policy invites it. | **Fixed, four ways.** (1) **Freeze protocol** — new SCOPE D19: the two global lexicons are authored *before* the corpus and their sha256 committed to `evals/fixtures/lexicon_manifest.json`; any later edit is a reviewed change. (2) **New gated metric M6_lex** = manifest hashes match ∧ no cue/anti entry occurs in exactly one fixture base article (`df(e) = 1` is the memorization signature; `df(e) = 0` is fine). Offending entries are printed. (3) **New gated ablation M1_amb_abl** — the ambiguous gate recomputed with every company's `context_terms`/`anti_terms` emptied, floor 0.70, backed by an authoring rule that ≤5 fixture positives may be `cue_free`. (4) The false claim is **withdrawn in the text**, replaced with an explicit statement of when it does and does not hold. SCOPE D4 was rewritten so outcome-tuning of weights/θ stays allowed while growing lexicons to fit fixtures does not. |
| E2 | evals | major | `U_amb`'s denominator was derived from `data/common_words.txt` — engine data the implementation owns — so dropping `all`/`cat` would simultaneously change detection *and* move those traps out of the hard subset into the forgiving M1. The "label-independent, cannot shift" claim was untrue. | **Fixed.** `U_amb` is now defined exclusively from a committed frozen file, `labels/weak_surfaces.json` (every weak alias plus every collision ticker *as of fixture authoring*), with an example of its shape. Editing `common_words.txt` can no longer reshape the gate. `run.py` prints a report-only diff between the frozen inventory and the live lexicon so intentional evolution stays visible. |
| E3 | evals | major | M2's ground truth had no committed first-class artifact (group assignments existed only in `expected.json`, declared informational; `labels/` held no group file), and nothing verified the committed feed XML still matched `generate.py --seed 4242`. | **Fixed.** `labels/story_groups.json` (article id → group id) is now a committed, hand-reviewed first-class truth file emitted by the generator, and M2's `same_true` reads it; `expected.json` stays informational. A new test, `test_fixtures_regenerate_identically`, re-runs `generate.py --seed 4242` into a temp dir and asserts byte-identity with the committed `feeds/*.xml` **and** `story_groups.json`, so a hand-edit fails CI. A truth-artifact table at the top of §2 names every gated metric's committed source. |
| E4 | evals | major | M3 conditions on predicted appearances, and the M1/M1_amb slack (~12 tolerated misses) is enough to curate the 12 designed count-vs-placement traps out of `O` and then score ~1.0 on the easy remainder. The "\|O\| ≥ 60" guarantee was a property of the labels, not of the observed denominator. | **Fixed.** New gated **M3_cov**: `run.py` asserts the *observed* `\|O\| ≥ 55` **and** that all 12 designated ordering-trap pairs (tagged `ordering_trap_group` in `mentions.json`) are present in `O`; failing coverage fails M3 regardless of its value. A report-only **M3_strict** is printed — the same score over label-truth pairs where a missing predicted appearance scores 0 — making the detection↔ranking coupling visible instead of exploitable. |
| E5 | evals | major | M4 step 1's expected selection ("computed from labels + thresholds") was underdefined: labels recorded tiers, not relevance, so context-tier stories could land either side of `min_relevance` — and resolving it from stored appearances would make the check circular. | **Fixed.** Three changes. (1) `mentions.json` now records the placement facts the formula needs — `mention_count`, `title_hit`, `lede_hit` — hand-counted, with inheritance guaranteed by a strengthened generator constraint (alternate headlines preserve the *count* of title surfaces, not just presence). (2) The derivation is written out in EVALS (`label_relevance` → `label_story_relevance` → selection) and implemented in `derive_expected.py`, which imports nothing from `src/tickerpress`. (3) A **relevance band rule** forbids any labeled story from landing within ±6 of a company's `min_relevance`/`alert_min_relevance`; combined with the discrete attainable-value set this makes every story decidably in or out and stable under a ±1-mention difference. `labels/expected_digest.json` is committed and asserted two ways: it must equal a fresh derivation, and the engine's step-1 item set must equal it. |
| E6 | evals | major | M5's two runs share one interpreter and therefore one `PYTHONHASHSEED`, so set/dict iteration-order nondeterminism reproduces identically and passes — the most common class of Python determinism bug is invisible to the gate that exists to catch it. | **Fixed.** M5's second pass now runs **in a subprocess with a different explicit `PYTHONHASHSEED`** (0 vs 12345) and the comparison happens across the process boundary on serialized dumps. Golden sha256 hashes of the step-1 digest `body_text` and the article+mention dump are committed under `evals/fixtures/golden/` and asserted by `test_golden_hashes`, catching fixture/template drift between commits (and pinning the D14 footer). SCOPE FR-16 now states the cross-`PYTHONHASHSEED` requirement and forbids unsorted-collection iteration from reaching an output. |
| E7 | evals | minor | Baseline scores were estimated ranges, not measured values (CONVENTIONS.md requires EVALS.md to state what the baseline scores), and nothing enforced the claimed margins — if naive M1 lands at 0.88, the "16-point margin" silently becomes 4. | **Fixed.** The baseline table is explicitly labelled provisional with a stated obligation to replace it with measured values when fixtures land, and `test_naive_margins` now asserts the margins at run time: `gate − naive_live ≥ 0.10` for M1, M1_amb, M1_amb_base, M1_amb_abl and M3; `≥ 0.50` for M2 `R_pair`. M2 `P_pair` is exempted with a stated reason (the URL-only clusterer trivially scores 1.0 there; `R_pair` carries the margin). An accidentally-easy corpus now fails CI instead of quietly hollowing out a gate. |
| E8 | evals | minor | `M2_trap = 0` is vacuous when all 15 no-link pairs are "below τ by construction" — it never probes the genuinely hard near-threshold region. Also `P_pair = 0/0` was undefined when nothing is clustered. | **Fixed.** Each `no_link.json` pair now carries `band: "near" \| "far"`, with **5 pairs authored into J ∈ [0.40, 0.60)** (sharing a quoted press-release paragraph). New gated **M2_near**: ≥4 of those 5 must compute J ≥ 0.40 while still staying apart, so the trap gate binds just under τ and a normalization change that pushes everything to J ≈ 0 fails. `run.py` prints observed J for all 15 pairs. `P_pair` is defined as **0.0** when the predicted-pair set is empty (and `M2_f1 = 0.0` when P+R = 0), so the never-cluster degenerate fails on `P_pair` as well as `R_pair`. |
| E9 | evals | minor | Variant inheritance re-counts the same disambiguation decision up to 5×, so a size-5 group's base costs 5 FNs while a singleton costs 1; the effective independent evidence behind the headline gate is thin (~20 weak-only positives + 16 traps). | **Fixed, all three sub-recommendations.** (1) Base-level M1 is printed report-only alongside the whole-corpus number, so group-size weighting is visible. (2) New gated **M1_amb_base** — the ambiguous subset over the 68 base articles only, floor 0.82 (3 points below M1_amb because the sample is thinner and each error costs ~2.5 points) — one vote per independent authoring decision. (3) The corpus grew by 6 weak-only ambiguous base positives (positive-ambiguous 14 → 20; bases 62 → 68; archived items 102 → 108), thickening the genuinely hard subset. All dependent counts were updated across the three docs, and §4 now carries a table of **asserted fixture floors** that `run.py` hard-checks before computing any metric. |

## Cross-doc consistency changes made while resolving the above

- FR ids unchanged (FR-1 … FR-16); non-goals gained item 10 (no per-alias/
  per-company thresholds), pushing the old item 10 to 11.
- New decisions: **D19** (lexicon freeze protocol). **D4**, **D8**, **D14**,
  **D18** rewritten.
- New metric names, used identically in all three docs: `M1_amb_base`,
  `M1_amb_abl`, `M2_near`, `M3_cov`, `M6_lex`, plus report-only `M3_strict`.
  Every one has a row in the §5 gate table and a test name in §7.
- New entity field `Article.content_token_count` (D4) with SQL, CHECK, and
  example-record coverage.
- FR-8's rounding is now pinned to `round_half_up(x) = floor(x + 0.5)` rather
  than Python's banker's `round`, because the M4 band rule depends on the
  exact attainable-value set `{6,13,19,25,31,38,44,50,56,63,69,75,81,88,94,100}`
  (banker's rounding would yield 12 and 62 instead of 13 and 63). Stated in
  SCOPE FR-8 and DATA_MODEL §2.8.
- FR-3 now specifies that `-`, `/`, and non-abbreviation `.` are token
  separators, which is what makes `Meta` matchable inside `Meta-analysis`
  (required by the `hyphen_compound` feature).
- Fixture corpus counts updated everywhere: 68 bases / 40 variants / 108
  archived items / 72 true same-story pairs / 15 no-link pairs (5 `near`).
- New committed fixture artifacts: `labels/weak_surfaces.json`,
  `labels/story_groups.json`, `labels/expected_digest.json`,
  `lexicon_manifest.json`, `golden/`, `derive_expected.py`. New lexicon file
  `data/cues_anti.txt` was also added to both docs' file lists — FR-6 had
  always referenced anti-cues but no file existed for them.
