# FormCoach — Evals

## What this product lives or dies on

1. **Form-fault detection from pose keypoints** (FR-7/8/9/10): given a noisy
   keypoint time-series, segment reps correctly, measure joint geometry
   accurately, and emit exactly the faults that are really there — with no
   confident output on unusable input. If this is wrong, the flagship feature
   is worse than useless (it mis-coaches).
2. **Science-compliant programming and progression** (FR-3/6): every generated
   program must satisfy the research-derived constraints it claims to encode
   (volume bands, frequency, RIR ramp, deload, rep ranges), and progression
   decisions must follow the double-progression/autoregulation rules exactly.
   If this is wrong, "science-based" is marketing.

Everything else (CRUD, media manifest plumbing, CLI) is covered by ordinary
tests, not eval gates.

## Metrics

All metrics are implemented in `evals/metrics.py` and computed exclusively
against committed fixtures with the offline adapters (`FixturePoseEstimator`,
`LocalMediaResolver`, in-memory store). No network, no clock, seeds fixed.

### M1 — Fault detection macro-F1 (capability 1)

Unit of prediction: an **applicable (clip, rep, rule)** triple — a rule is
applicable when the clip's view is in the rule's `views` and its required
keypoints pass visibility screening. For each fault class `c` over all
applicable triples:

```
TP_c = #(truth = fault_c ∧ pred = fault_c)
FP_c = #(truth = ok      ∧ pred = fault_c)
FN_c = #(truth = fault_c ∧ pred ∈ {ok, not_assessed})
P_c = TP_c/(TP_c+FP_c)   R_c = TP_c/(TP_c+FN_c)   F1_c = 2·P_c·R_c/(P_c+R_c)
```

(F1_c = 0 when the denominator of P or R is 0.)
**Macro-F1 = mean of F1_c over the 13 catalog fault classes** (every class has
≥ 6 positive instances in the fixture set, so no class is vacuous). A `pred =
not_assessed` on an applicable triple counts as a miss — the engine cannot
dodge the metric by refusing.

### M2 — Rep-count exact accuracy (capability 1)

Over the `N_valid` clips that pass screening:

```
M2 = (1/N_valid) · Σ 1[pred_rep_count == true_rep_count]
```

### M3 — Feature measurement error (capability 1)

Over every (rep, feature) instance with ground truth (all reps, faulted or
not):

```
M3a = mean |measured_deg  − true_deg |   over angle features (trunk_lean_deg, fppa_deg, elbow_angle_deg, hip_ext_angle_deg, layback_deg)
M3b = mean |measured_frac − true_frac|   over ratio features (depth_ratio, bar_drift_frac, hip_dev_frac, hip_shoulder_rise_ratio, wrist_gap_frac)
```

Measurement drives everything downstream; gating it separately stops a lucky
threshold from masking a broken goniometer.

### M4 — Screening accuracy (capability 1, the "refuse to guess" behavior)

Over **all** fixture clips, valid and degraded:

```
M4 = (#valid clips accepted + #degraded clips rejected with reason) / N_clips
```

### M5 — Program constraint satisfaction (capability 2)

Generate a program for each of the 120 fixture profiles (fixed seed each).
For each program evaluate the machine-checkable constraint list below; score:

```
M5 = Σ_programs Σ_constraints passed / (120 · |C|)
```

Constraint set `C` (each cites its FR-3 clause): (1) per-muscle planned weekly
sets within [MEV, MRV] for trained muscles in weeks 1–4, and ≥ MEV for
emphasized muscles; (2) every trained muscle hit on ≥ 2 distinct days/week;
(3) emphasized-muscle sets non-decreasing weeks 1→4; (4) week 5 sets ≤ 50 % of
week 4 and RIR ≥ 4; (5) RIR targets non-increasing weeks 1→4 within 3→1;
(6) rep ranges match goal/role table; (7) only profile-equipment exercises;
(8) per-session per-muscle sets ≤ 10; (9) compounds ordered before isolation;
(10) required movement patterns of the split all covered; (11) rest times in
the FR-3 bands; (12) same profile + seed ⇒ byte-identical program (run
twice).

### M6 — Progression decision accuracy (capability 2)

24 golden scenarios (history + current prescription + week → expected action
∈ {increase_load, hold, decrease_load, add_set, deload_recommend} and expected
load to the rounding increment):

```
M6 = (#scenarios where action AND load both match) / 24
```

## Fixture strategy

Everything committed under `evals/fixtures/`, regenerable byte-identically by
committed seeded scripts. Nothing is produced by running the engine itself —
ground truth always comes from generation parameters or hand-authoring, so the
evals cannot be circular.

### Pose clips — `evals/fixtures/poses/*.keypoints.json` + `labels.json`

Generated by `evals/fixtures/generate_poses.py --seed 20260731` (committed;
CI can re-run and diff). A 2-D kinematic stick-figure simulator:

- **Skeleton:** COCO-17 keypoints from body-segment lengths per de Leva (1996)
  anthropometric parameters; three body sizes.
- **Motion:** per-exercise joint-angle trajectories (raised-cosine
  interpolation between start/extremum/end angles per rep phase), 4–6 reps per
  clip, fps 30, small per-rep tempo variation (seeded).
- **Fault injection:** faults are *parameters* — e.g. bottom knee/hip angles
  for shallow depth, trunk-pitch profile for lean, frontal knee-x offset for
  valgus (projected FPPA), hip-lead timing offset for `hips_rise_early`,
  wrist-x offset for `bar_drift`, elbow-extension ceiling for lockout faults.
  Each injected fault clears its threshold by ≥ 2× the noise-induced feature
  σ; each clean rep sits the same margin inside. ~10 % of reps are deliberately
  **near-threshold**, labeled by their exact pre-noise feature value — these
  keep the gate honest about measurement precision.
- **Noise & realism:** orthographic projection to normalized image coords,
  Gaussian keypoint jitter (σ 0.004–0.010 normalized units, varied per clip
  and recorded), per-keypoint confidence model, occasional confidence dips.
- **Degraded clips:** 6 clips with sustained conf < 0.3 on required keypoints
  in > 30 % of frames (simulated occlusion) — must be rejected (M4).
- **Composition:** 64 clips ≈ squat side ×10, squat front ×10, deadlift side
  ×12, push-up side ×10, ohp side ×8, ohp front ×8, degraded ×6. Every fault
  class appears ≥ 6 times; ≈ 30 % of applicable (rep, rule) triples are
  faults.
- **Ground truth (`labels.json`):** per clip — exercise, view, fps, validity;
  per rep — true boundary frames, exact pre-noise feature values, fault
  labels. All derived from generator parameters at generation time.

Synthetic-first is a deliberate choice: it is the only way to get exact
ground-truth angles and deterministic CI. A small curated set of real clips
(keypoints extracted once with the live adapter, hand-labeled, then committed)
is a planned *addition* post-MVP and will never replace the synthetic gates.

### Programming fixtures

- `evals/fixtures/profiles_grid.json` — 120 profiles: goals(3) ×
  days_per_week(2–6) × experience(2: beginner, advanced) ×
  equipment({full gym}, {dumbbell, bodyweight}) × emphasis({}, {quads, chest}).
- `evals/fixtures/progression_golden.json` — 24 hand-authored scenarios with
  expected action + load, each annotated with the FR-6 clause and the source
  concept it exercises (double progression top-of-range trigger, RIR
  under/overshoot autoregulation per the Zourdos/Helms RIR scale, missed-volume
  hold, e1rm-drop reactive deload, equipment increment rounding, deload-week
  behavior).

## Naive baselines and gates

| Metric | Naive baseline | Baseline score | Gate | Rationale |
|---|---|---|---|---|
| M1 macro-F1 | flag every applicable (rep, rule) as fault | ≈ 0.46 (recall 1.0, precision ≈ fault base rate 0.30) — and never-flag scores 0.00 | **≥ 0.80** | Near-threshold reps + jitter make 1.0 unreachable without fixture overfitting; design margins put a correct implementation at ≈ 0.85–0.92. 0.80 is far above flag-all and fails if segmentation, smoothing, or any single rule regresses. |
| M2 rep count | peak-count raw unsmoothed signal, no prominence/duration hysteresis | ≈ 0.45 (jitter creates spurious extrema on most clips) | **≥ 0.90** | Hysteresis segmentation should miss only the harshest-jitter clips; 1.0 not gated to allow the recorded worst-case σ clip to be genuinely hard. |
| M3a angle MAE | features from single raw extremum frame, no smoothing | ≈ 9° | **≤ 5°** | Noise floor after smoothing ≈ 2–3° by construction (jitter σ vs segment lengths); 5° passes a correct pipeline, fails a broken one, and is tighter than the smallest threshold margin (valgus 12°). |
| M3b ratio MAE | same | ≈ 0.06 | **≤ 0.03** | Same argument in ratio units (smallest margin: depth_ratio 0.03). |
| M4 screening | accept everything | 0.91 (58/64) | **= 1.0** | Deterministic rule on committed clips; any miss means the "refuse to guess" behavior (US-7) broke. |
| M5 constraints | "3×10 everything, same full-body session daily, no deload, fixed rep range, no RIR" | ≈ 0.55 (fails volume bands at high frequency, deload, RIR ramp, goal rep ranges, ordering) | **= 1.0** | The generator is deterministic and defines these constraints itself — any violation is a bug, same rationale as Orbit's 100 % safety gates. |
| M6 progression | always increase load by one increment | ≈ 0.33 (8/24) | **= 1.0** | 24 hand-authored cases of a deterministic rule set; partial credit would hide broken autoregulation. |

Fault base rate, clip counts, and the 0.85–0.92 expectation are fixed by the
generator's committed parameters; if fixture composition changes, this table
must be re-derived in the same commit (checked in review).

## How the suite runs

Per workspace conventions:

```bash
cd projects
uv run python formcoach/evals/run.py     # scorecard: metric | value | gate | PASS/FAIL, exit 1 on any FAIL
uv run pytest formcoach/                  # unit/integration tests + evals/test_gates.py
```

- `evals/run.py` — zero-config: loads fixtures, runs the engine through the
  offline adapters, prints the table above with actual values, exits non-zero
  if any gate fails.
- `evals/test_gates.py` — one pytest per gate (`test_gate_m1_fault_macro_f1_fr9`,
  `test_gate_m5_program_constraints_fr3`, …); test names reference FR ids so
  the FR → test mapping is auditable.
- `evals/metrics.py` — pure metric functions shared by both entry points.
- Hermetic: no network, no wall clock (all timestamps come from fixtures),
  seeded randomness only. The optional live pose adapter is never imported by
  the eval path.
